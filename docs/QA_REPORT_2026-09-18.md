# Senior QA Report — 18 September 2026

## Release recommendation

**Do not publish this build to the public domain yet.** It is strong enough for a committee demo and on-device rehearsal, but the organiser console, server API, onboarding requirement and cultural sign-offs contain launch blockers.

## Test evidence

- `npm run typecheck`, `npm run lint`, `npm run test`, `npm run validate:content` and `npm run build` pass.
- 18 schedule/date tests pass.
- Browser smoke test covered Home, Programme, Map deep link, Trail, trail detail, invalid QR recovery, My Festival, Help, Membership, Organiser and 404 routes.
- No broken images appeared on the tested routes.
- Content validation reports 12 trail stories awaiting committee approval.

## Findings

| ID | Severity | Area | Finding | Evidence | Recommended action |
|---|---|---|---|---|---|
| QA-01 | P0 | Security | The organiser console is public and can alter the programme and emergency announcements. | `frontend/src/app/App.tsx:119`, `frontend/src/pages/Admin.tsx:31` | Protect the route and every write endpoint with server sessions, CSRF and an organiser role before any public deployment. |
| QA-02 | P0 | Backend | Production API mode cannot run. The PHP backend only implements `/api/health`; the frontend expects public data and five auth endpoints. | `backend/public/index.php:9`, `frontend/src/lib/repositories/repository.ts:14`, `frontend/src/lib/auth/auth.ts:67` | Implement the API and migrations, or deploy explicitly as a static seed demo with organiser controls removed. |
| QA-03 | P1 | Requirements | Registration is no longer the first interface. The app opens directly to Home and sign-in appears only after selected actions. This reverses the agreed onboarding requirement. | `frontend/src/app/App.tsx:104`, `frontend/src/components/SignInSheet.tsx:6`, `docs/SHIP_CHECKLIST.md:10` | Decide with the product owner: mandatory first-screen registration or optional guest mode. Update code and all docs to one decision. |
| QA-04 | P1 | Live operations | The organiser screen says changes appear on every visitor screen, but updates only cross tabs in the same browser profile. ## Deployment gate

Public deployment requires QA-01, QA-02, QA-03, QA-04, QA-05, QA-07 and QA-09 to close. A password-protected committee demo may ship earlier if `/organiser` is removed from that build and the demo code/status is clearly labelled.
